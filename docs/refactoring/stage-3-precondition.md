# Предусловие этапа 3: одна папка данных — одна копия программы

Дата: 12 ноября 2026. План: [architecture-refactoring-plan.md](../architecture-refactoring-plan.md).
Сделано перед этапом 3 (SQLite), потому что обе вещи, о которых здесь речь, ломают как раз хранилище.

## Зачем

Сегодня `free_port()` просто берёт следующий свободный порт, поэтому вторая копия программы
спокойно стартует с той же папкой данных и:

- обе спрашивают пользователя про сохранённую очередь и **отправляют одни и те же незавершённые
  задания заново** — двойная генерация и двойные записи в Библиотеке;
- перезаписывают друг другу `queue.json`, `library.json` и `config.json` (последняя запись выигрывает);
- с этапа 3 открывали бы один и тот же файл SQLite из двух процессов.

Второй риск — **где** лежит папка данных. После перехода на SQLite сетевой диск (SMB) перестаёт быть
просто «медленным»: WAL-журнал поверх сети и обрыв связи — это повреждённая база. Синхронизируемая
папка (OneDrive, Dropbox, Яндекс.Диск, Google Drive, iCloud) копирует файл в момент записи.

## Что сделано

### 1. Один экземпляр на папку данных

[app/instance.py](../../app/instance.py) — именованный мьютекс Windows, имя которого выводится из
полного пути папки данных (`Local\h3studio-data-<sha1>`). Система освобождает мьютекс, когда процесс
завершается, — при падении, из диспетчера задач, при снятии питания. Поэтому не остаётся «замка»,
который после сбоя запретил бы запуск (файл-замок пришлось бы чистить вручную и он врал бы).

- `instance.acquire(path)` — `True`, если мы единственная копия; `False`, если папку уже держит другая.
- `instance.publish(path, port)` пишет `instance.json` (`pid`, `port`, `url`, время) через атомарную
  запись; `published(path)` читает его и **игнорирует запись мёртвого процесса**; `forget()` удаляет
  только свою запись.
- [app/main.py](../../app/main.py): мьютекс берётся до запуска сервера. Вторая копия показывает
  MessageBox «Minimax H3 Workspace уже запущена» с адресом открытой программы и выходит с кодом 3.
- [app/server.py](../../app/server.py), `main()`: то же для запуска из `app/start.bat` (там нет окна,
  поэтому сообщение печатается в консоль, код выхода тот же 3).

Разные папки данных по-прежнему работают одновременно — вторая библиотека это законный сценарий.
Проверено тестом: две копии на разных папках не мешают друг другу.

### 2. Предупреждение о папке данных

[datadir.check_location(path)](../../app/datadir.py) возвращает текст для пользователя или `None`:

- UNC-путь (`\\server\share\…`) и диск `DRIVE_REMOTE` — «сетевой диск, база может повреждаться»;
- путь внутри OneDrive / Dropbox / Google Drive / Яндекс.Диска / iCloud Drive / MEGA — «синхронизация
  может копировать базу во время записи».

Это предупреждение, а не запрет: работать в такой папке можно, программа не отказывается стартовать.

- `App` считает его один раз при старте (`self.data_dir_warning`);
- `GET /api/status` отдаёт аддитивное поле `data_dir: {path, warning}`;
- окно показывает предупреждение всплывающим сообщением на 12 секунд и запоминает в `localStorage`
  (`h3s-data-warning:<путь>`), чтобы не повторять его на каждом запуске. У `toast()` появился
  необязательный второй параметр — длительность.

## Контракты

| Что | Изменение | Совместимость |
| --- | --- | --- |
| `GET /api/status` | добавлено `data_dir: {path, warning}` | аддитивно; старые клиенты не читают |
| `instance.json` в папке данных | новый файл (`pid`, `port`, `url`, `started`) | не читается старыми версиями, ничего не ломает |
| Код выхода второй копии | `3`, сообщение пользователю | новое поведение, окно и консоль |

Маршруты, `agent.json`, API агента и MCP-инструменты не менялись.

- `test_instance_guard.py` (6) — настоящие два процесса: вторая копия получает «busy»; после выхода
  первой папка снова свободна; две разные папки не мешают друг другу; `instance.json` от живого и
  мёртвого процесса; `forget` не удаляет чужую запись.
- `test_data_location.py` (4) — локальная папка чистая; сетевой путь и синхронизируемые папки дают
  предупреждение с названием сервиса и советом, что делать; несуществующая папка не роняет проверку.
- `boot_smoke.py` (+2 проверки) — `/api/status` называет папку данных и не предупреждает о локальной;
  работающая копия публикует `instance.json` с тем же портом и папкой.
- Ручная проверка двумя настоящими процессами `server.py` на одной папке: первая копия работает,
  вторая печатает «уже запущена … http://127.0.0.1:8899» и выходит с кодом 3; после снятия первой
  (жёстко, `Stop-Process -Force`) новая копия папку занимает — мьютекс освободился вместе с процессом.

## Ограничения

1. **Мьютекс — в пространстве `Local\`, то есть на сеанс Windows.** Два пользователя в разных сеансах
   на одной папке друг друга не увидят. Для общей папки установки это остаётся риском; полностью
   закрыть его можно только `Global\`-мьютексом, а он требует прав, которых у обычного пользователя
   может не быть. Папка данных по умолчанию персональная, поэтому выбран `Local\`.
2. **`instance.json` может остаться после жёсткого завершения.** Это безвредно: `published()` сверяет
   процесс и не выдаёт мёртвую запись за живую; при следующем чистом выходе файл удаляется.
3. **Предупреждение о папке — эвристика** (UNC/сетевой диск + известные имена папок). Перемещение
   папки во время работы не перепроверяется: нужен перезапуск.
4. **Проверка не запрещает** работу в сетевой папке — только сообщает. Запрет имел бы смысл вместе с
   SQLite (этап 3), но и тогда решение за пользователем: у некоторых библиотека лежит на NAS.
