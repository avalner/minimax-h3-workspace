## 2. Параметры задания: явные, а не по подписи

Раньше окно восстанавливало модель регулярным выражением по подписи (`/fused turbo/i` на
`meta.sub`): подпись — текст для человека, её могли поменять, сократить или перевести, и тогда
восстановленное задание молча получало другую модель.

Теперь:

- новые задания пишут в `meta` сами параметры: `model` и `acceleration` (окно, референсы, агент);
- [jobmeta.py](../../app/jobmeta.py) — единственное место, которое читает старую подпись, и он же
  помечает происхождение значения:

  | `params_source` | Что значит | Что делает окно |
  | --- | --- | --- |
  | `record` | параметры есть в самой записи | ставит их молча |
  | `legacy` | прочитано из подписи старой записи | ставит и пишет «восстановлено по подписи — проверьте» |
  | `unknown` | в записи не сохранилось ничего | ставит FastH3/«обычное» и говорит об этом |

- `/api/job/{id}` прогоняет `meta` через нормализатор для всех четырёх источников ответа (живое
  задание, запись Библиотеки, память исхода, задание прошлого запуска) — окно больше не разбирает
  подписи и не выдаёт догадку за точность.

## 3. Первые внешние файлы окна

**`/ui/js/api.js`** — правила HTTP в одном месте: неверный статус превращается в `ApiError` с
`status`/`code`/`hint` и **словами сервера** (раньше `new Error(j.error)` на объекте давал
`[object Object]`), `timeout` действительно обрывает запрос через `AbortController`, можно передать
свой `signal`. Автоматических повторов нет: POST генерации не повторяется транспортом.

**`/ui/js/events.js`** — транспорт событий: одно соединение (повторный `connect` закрывает
предыдущее), переподключение с растущей задержкой (0.5 с → 15 с, сброс после успешного открытия),
разбор сообщений, битые строки отбрасываются. Что значит сообщение — по-прежнему решает страница
(`onServerMessage`), модуль ничего не знает про очередь и задания.

Страница остаётся одним классическим скриптом: модуль нельзя импортировать из него, поэтому оба
модуля выставляют себя на `window` (`h3Api`/`h3Events`), а страница вызывает их в
`postJSON`/`connectEvents`. Пока модуль не загрузился, страница ждёт его и, если он так и не пришёл,
пишет в консоль и показывает сообщение — тихой потери событий нет.

**`/ui/css/app.css`** — весь прежний `<style>` (99 140 символов) перенесён **точно** и в том же
порядке; в `index.html` вместо него `<link rel="stylesheet">`. Группировка на смысловые файлы
(база/компоненты/режимы) — следующий шаг: при одном файле порядок каскада гарантирован, при
неудачной группировке дизайн ломается, а проверить это глазами в этой сессии нельзя.

## 4. Упаковка и content type

- `web.static("/ui", …)` заменён на `h_ui`: тип отдаётся по явной таблице (`text/javascript`,
  `text/css`, `video/mp4`, …), путь проверяется через `is_relative_to`, файлы других типов не
  отдаются. Причина: `web.static` берёт тип из реестра Windows, где `.js` нередко `text/plain`, —
  браузер отказывается исполнять модуль, и окно открывается пустым.
- `h3studio.spec` включает **всю** папку `ui` (`(ui, "ui")`) вместо перечисления `index.html` и
  `previews`: новый js/css-файл больше не может не попасть в собранное приложение.
- `boot_smoke.py` теперь проверяет это на живом приложении: `app.css` → `text/css`, `api.js` и
  `events.js` → JavaScript, превью → `video/*`, `%2e%2e%2fserver.py` → отказ, страница ссылается на
  файлы и не содержит `<style>`.

## 5. Контракты

Публичные маршруты те же (140, [contracts.md](contracts.md)); `/ui/*` отдаётся иначе внутри, но теми
же путями:

| Что | Было | Стало |
| --- | --- | --- |
| `/ui/*` | `web.static` (тип из реестра) | `h_ui`: явная таблица типов, `no-cache`, только известные расширения |
| `meta` в `/api/job/{id}` | без параметров модели | аддитивно `model`, `acceleration`, `params_source` |
| CSS | inline `<style>` | `/ui/css/app.css` |
| события | inline WebSocket | `/ui/js/events.js` (через `window.h3Events`) |
| HTTP окна | inline `postJSON` | `/ui/js/api.js` (через `window.h3Api`), старый код остался запасным путём |

## 6. Что осталось в этом этапе (честно)

1. **`state.js` не выделен.** Состояние очереди (`QUEUE`, `qAdd`, `qHandle`, `qRender`) — самый
   связанный кусок страницы; выносить его вместе с переносом режимов безопаснее, чем отдельно.
2. **Компоненты и режимы (пункты 4–5) не переносились.** Это следующий шаг: video → images →
   refs/actor/swap → long → montage → настройки/агент, каждый с mount/dispose.
3. **CSS — один файл, а не группы.** Перенос точный, порядок сохранён; деление на группы — отдельный
   проход, когда будет чем проверить вид (скриншоты/ручной просмотр).
4. **Не все `fetch` страницы идут через `api.js`**: переведены `postJSON` (все POST) и подключение
   событий; остальные GET-чтения (статус, библиотека) пока со своими `fetch` — следующий шаг,
   вместе с `state.js`.
5. **Проверить окно глазами в этой сессии нельзя** (нет интерактивного браузера под рукой): синтаксис
   обоих модулей и всех блоков `<script>` проверен `node --check`, отдача файлов и типы — живым
   `boot_smoke`, но внешний вид страницы после переноса CSS не смотрели. Это единственный риск
   коммита, и он записан здесь.
