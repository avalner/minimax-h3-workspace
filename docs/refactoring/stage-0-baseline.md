Версии приложения зафиксированы в [requirements.txt](../../requirements.txt), проверочные — в
[requirements-dev.txt](../../requirements-dev.txt). Обновление зависимости: поставить новую версию,
прогнать `tests/run.py` и записать фактические версии в эти файлы — «просто поставить последнюю»
здесь не считается проверкой.

## 2. Как запускаются проверки

```powershell
# в этой среде: пакеты берутся из переносимого ComfyUI, в него ничего не ставится
$env:PYTHONPATH = "I:\Video Generation\ComfyUI_windows_portable\python_embeded\Lib\site-packages"
_test\venv\Scripts\python.exe tests\run.py

# на машине, где aiohttp стоит в самом интерпретаторе
python tests\run.py
```

`tests/run.py` — общий запуск. Каждая проверка идёт отдельным процессом со своей временной папкой
`H3STUDIO_DATA`, своим `agent.json` и своим `TEMP`, поэтому пользовательская библиотека и рабочий
ComfyUI не читаются и не пишутся. Группы (`--list`, `--only <группа>`, `--all`):

| Группа | Что проверяет | Сеть |
| --- | --- | --- |
| `unit` | хранилище, завершение задания, восстановление очереди, старые файлы | нет |
| `boot` | приложение запускается из исходников и отвечает на свои запросы | только 127.0.0.1 |
| `graphs` | графы генерации не изменились (`video_fused_graph_test.py`) | нет |
| `watchdog` | решения сторожа видеокарты (`gpu_watchdog_test.py`) | нет |
| `api` | API агента на поддельном ComfyUI (`agent_api_smoke.py`) | только 127.0.0.1 |
| `mcp` | MCP-сервер через stdio (`mcp_stdio_smoke.py`) | нужен node и запущенное приложение |

Код выхода: `0` — всё прошло, `1` — что-то не прошло, `2` — запустить не удалось. Проверка, которая
сама говорит «здесь не могу» (код 3), печатается как пропущенная и **не** считается пройденной.

## 4. Найденное ограничение среды (не приложения)

`tempfile.mkdtemp` создаёт папку с режимом 0700. На Windows у такой папки свой список разрешений,
который **не наследует** права родителя, и под ограниченным токеном этой среды (права выданы
наследуемой записью на каталог проекта) программа не может создать файл в папке, которую только что
сделала сама. Из-за этого `agent_api_smoke.py` падал на первом же `mkdir`, не дойдя до приложения.

Исправлено в тестах, а не в приложении: `tests/tempdir.py` создаёт папку обычным `mkdir` (наследует
права). Тот же приём — в `tests/unit/support.py`. Тесты после этого проходят и на `HEAD`, и на новом
коде, то есть контракт API сохранён. На обычной машине без ограничений этот helper работает так же.

## 5. Контракты: что нельзя ломать

Полная карта — [contracts.md](contracts.md), она пересобирается командой
`python tests/contract_map.py > docs/refactoring/contracts.md`.

- **HTTP: 140 маршрутов.** Группы: `/api/...` окна (статус, установка, модели, LoRA, библиотека,
  файлы, workflow, длинные проекты, чаты, агент), `/api/agent/v1/...` — контракт для других программ,
  `/ui/...` — статика. Ответы, которые читает окно, перечислены в карте.
- **События в окно: 22** (`done`, `error`, `interrupted`, `stage`, `preview_anim`, `engine`, `notice`,
  `setup`, `mdl`, `loradl`, `ffmpegdl`, `input`, `delta` и т. д.).
- **Публичные идентификаторы:** `prompt_id` (он же id задания для агента и окна), `library.id`,
  `asset_id`, `run` длинного проекта. Переименовывать их нельзя.
- **Безопасность:** привязка к `127.0.0.1`, проверка origin (`origin_ok`), ключ агента в
  `agent.json`, ограничение путей входных файлов, Windows Job Object для дочерних процессов.

## 7. Зафиксированная семантика (менять только осознанно)

Это то, что план требует «сначала зафиксировать, потом трогать»:

- **Очередь** (`queue.json`): записи без `graph` игнорируются; записи старше 7 дней игнорируются;
  пустая очередь удаляет файл. Восстановление спрашивает пользователя («Продолжить очередь?»),
  отказ = `POST /api/queue/discard` навсегда забывает записи.
- **Черновики картинок** (`self.pending`): только в памяти, `PREVIEW_LIMIT = 40` (новые вытесняют
  старые с конца), в Библиотеку попадают только по кнопке «Добавить в библиотеку», после рестарта
  забываются. Долговечное восстановление заданий (этап 3) не должно сделать их долговечными.
- **`recent` / `history`**: по 200 записей, только для показа деталей уже завершённого задания.
- **Библиотека** (`library.json`): массив; запись без `id` отбрасывается; битый файл переименовывается
  в `library.json.broken-<дата>` и не затирается пустым списком. Так же ведёт себя `config.json`.
- **Идемпотентность агента**: словарь в памяти, 200 ключей, ключ → `prompt_id`, без отпечатка запроса;
  после рестарта ключи теряются (этап 4 должен сделать их долговечными).
- **Сторож заданий**: цикл 60 с; `queued` старше 240 с без записи в истории — ошибка; `running` молчит
  больше 900 с — ошибка, если в истории ничего нет; `running` в очереди молчит 600 с — перезапуск
  движка (локального).
- **`finish_job`** (до этапа 1): задание удаляется из очереди **до** поиска и регистрации результата.

## 8. Проверки, которые здесь выполнить нельзя

Перечислено явно, чтобы они не считались пройденными:

1. **MCP smoke** (`tests/mcp_stdio_smoke.py`): нужен node (есть, v24.18.1) и отдельный запущенный
   экземпляр приложения. Команда для отдельного запуска:
   `python tests/mcp_stdio_smoke.py` (в раннере — `--only mcp --all`).
2. **Сборка exe** (`app/build/h3studio.spec`): PyInstaller не установлен. Значит, и упаковка
   JS/CSS-файлов после разделения UI (этап 8) пока не проверена. План требует проверить это в этапе 8;
   лучше — заранее, спайком.
3. **Реальная генерация** (GPU, модели): планом не требуется как автоматическая проверка; графы и
   протокол проверяются поддельным движком.
4. **Окно pywebview**: пакет не установлен, окно не запускалось. Проверялось приложение без окна
   (`server.py`) и отдача `index.html` через HTTP.

## 9. Что сделано сверх буквы плана

- `tests/boot_smoke.py` — проверка «приложение запускается и отвечает»: без неё ошибка импорта или
  маршрута видна только пользователю.
- `tests/contract_map.py` + `docs/refactoring/contracts.md` — карта маршрутов и мест изменения
  состояния, которая пересобирается одной командой.
- `tests/fixtures/legacy/` — синтетические старые `config.json`, `library.json`, `queue.json` и
  `long/<run>/project.json` (без промптов пользователя и без токенов) и тест, что они читаются и
  переживают перезапись. Это заготовка для миграции этапа 3.
