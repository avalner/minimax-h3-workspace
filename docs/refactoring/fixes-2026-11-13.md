# Исправления по результатам проверки

13 ноября 2026. Основание: `review-2026-11-13.md` и уточнение пользователя о долговечности черновиков.

## Что исправлено

1. **Задания submitting/uncertain не удаляются при сохранении очереди.** save_queue обновляет известные записи и больше не считает отсутствие в UI-кэше основанием для удаления. Удаление заменённого элемента восстановления выполняется явно. Неопределённая отправка сохраняется после перезапуска и не отправляется повторно автоматически. Ключ повторного запроса и начальная запись задания резервируются одной транзакцией.
2. **Облачная финализация фиксирует результат перед удалением задания из очереди.** Долговечный task ID остаётся при ошибке записи/скачивания; повторяется только получение/регистрация готового результата. ID результата стабилен. После перезапуска уже скачанный файл не скачивается заново. Отмена облачного задания направляется в RunningHub, а не в адаптер ComfyUI.
3. **Путь к независимой копии сохраняется при добавлении черновика в библиотеку.** Переход фиксирует library payload, media и удаление из drafts в одной транзакции. Отказ записи оставляет черновик доступным. Для копий, созданных прежней ошибочной версией, file_path также проверяет сохранённый media.path. Одновременные нажатия «Добавить в библиотеку» не создают дубликаты.
4. **Неизвестная новая схема БД блокирует запуск пишущего приложения.** Проверка выполняется сразу после открытия соединения, до изменения настроек БД; соединение закрывается при отказе. App не подавляет SchemaVersionError.
5. **Черновики сохраняются после перезапуска именно как черновики.** Добавлена таблица drafts, загрузка при запуске, восстановление в WebSocket snapshot независимо от срока хранения исхода задания. Файлы новых черновиков ComfyUI копируются в DATA_DIR/drafts; файлы облака/FFmpeg остаются в их локальных назначениях. Убраны ограничения памяти, терявшие старые черновики, а списки разделов больше не скрывают черновики за лимитом истории. Черновики не записываются в library до явного keep.
6. **Idempotency сравнивает исходный запрос до случайных defaults и загрузок.** Одинаковый запрос без seed возвращает первоначальный seed и тот же job; случайные имена загруженных файлов не меняют fingerprint. Проверены повтор после рестарта и одновременные запросы. Изменение запроса при прежнем ключе по-прежнему даёт конфликт.
7. **Импорт STORE_ERRORS восстановлен.** Ошибка записи итогового состояния корректно попадает в диагностику вместо NameError.

Дополнительно закрыты связанные пробелы:

- остальные графовые режимы ComfyUI и RunningHub сохраняют submitting до удалённого POST, а не только после получения ID;
- FFmpeg получает долговечную запись; готовый монтаж регистрируется через общий MediaService, а сбой регистрации восстанавливается после запуска без повторного монтажа. Прерванный незавершённый монтаж отмечается как прерванный и не отправляется в ComfyUI;
- граф видео использует сохранённый в JobSpec снимок LoRA;
- обновлены README и проверки старых данных для схемы БД версии 2.

## Миграция

Шаг `0002-drafts` добавляет отдельное хранилище. Старые строки library, которые media однозначно помечает как `draft` без library_id, переносятся в drafts в одной транзакции. Библиотечные записи, уже отмеченные как сохранённые, остаются на месте. Перед миграцией используется существующий механизм резервной копии базы. Старые файлы не удаляются.

Записи ошибочно опубликованных ранее черновиков восстанавливаются с имеющимися ссылками на файлы. Миграция не может воссоздать файл, если его уже удалили до обновления. Новые черновики ComfyUI получают собственную локальную копию; при отказе копирования ошибка записывается в диагностику и media, исходная ссылка сохраняется.

## Границы работы

Исправлены найденные дефекты, долговечность черновиков и связанные пути регистрации/отправки. Дальнейшее сокращение ответственности route mixins остаётся отдельной архитектурной работой; исправления не означают, что всё приложение уже переведено на полностью независимые сервисы.
