### 6. Переименование и удаление проекта (`47e05d0`)

- `POST /api/projects/{id}/rename` — меняется только имя, id прежний (все записи, этапы и фильмы
  продолжают указывать на ту же работу).
- `GET /api/projects/{id}/assets` — всё, что в проекте: `library`, `drafts`, `stages`, `films`
  (фильмы сканируются из `LONG_DIR/*/project.json`, см. `webcommon.long_films`). Фильмом считается
  только то, где что-то есть — сцена с текстом, сделанная сцена или референсы
  (`webcommon.long_film_has_work`): студия, которую только открыли, заводит две пустые сцены, и
  предлагать их к переносу бессмысленно (`6ba5f4f`). Такая запись не создаётся и вовсе: `saveNow`
  пишет фильм, только если в нём что-то есть (или он уже был сохранён раньше).
- `POST /api/projects/{id}/delete` с `keep: {library, drafts, stages, films}` — выбранное получает
  метку «Основного» (файлы не двигаются), остальное удаляется: файлы `library`/`drafts` в корзину,
  `stages` и `films` — с диска (`drop_long_film`). Проект, у которого не удалось убрать файл в
  корзину, не теряет запись: она остаётся в «Основном» (`kept_back`), окно об этом говорит.
  «Основное» удалить нельзя; удаление активного проекта переводит активным «Основное».
- Окно: карандаш и крестик в списке проектов (у «Основного» крестика нет), диалог удаления с
  числами и выбором «что оставить» (по умолчанию ничего не выбрано, есть «Выбрать все»/«Снять
  выбор»), после удаления окно подчищает `LIB`/`DRAFTS`, перечитывает этапы и ждёт
  `h3LongProjectChanged` (фильм удалённого проекта не дописывается обратно, см. `_projectChanged`).

## Правила, которые нельзя сломать

- Проект ставится **при отправке**: `attach_job` / `begin_submission` / `queue_cloud` /
  `hold_preview` / монтаж. Не переносить на момент готовности. То же правило в окне: `qAdd` ставит
  активный проект, фильм студии — `root._project` (проект, в котором фильм начат).
- Этапы: ключи слотов проверяет `KEY_RE` в `routes/stages.py`; файл льётся после `postStage`,
  локальная копия `bm/<id>/…` удаляется только после успешной загрузки.
- Раздел refs-семейства пишет свою разметку: полосу этапов (`.st-bar`) нужно переносить, иначе
  раздел теряет кнопки этапов.
- `previewPanel.update()` очищает кадр только когда показывать нечего: показанный клип переживает и
  смену параметров, и отложенный `apply()` этапа.
- Поповер удаления считается в координатах раскладки (делится на зум) — иначе уезжает.
- Удаление: черновик → `/api/preview/{id}`, библиотечный → `/api/library/{id}`; файлы в корзину,
  при неудаче запись остаётся.
- `projectOk()` — единственный фильтр списков; после смены проекта вызывать `refreshProjectLists()`.
- Смена проекта в шапке: `selectProject`/`createProject` ждут `h3LongProjectChanged()`; `bmOpen`
  переключает проект до `_openStage`.
- «Основное» удалить нельзя: в него переносят работу. Удаление другого проекта — перенос выбранного
  меткой (файлы не двигаются) и удаление остального; файл, который не ушёл в корзину, оставляет свою
  запись в «Основном», а не исчезает вместе с проектом.
- Студия не дописывает фильм проекта, которого уже нет: `_projectChanged` сохраняет старый только
  пока проект есть в списке, иначе отменяет отложенное сохранение.
- Порожняя студия — не фильм: без текста сцены, готовой сцены и референсов фильм не сохраняется, а в
  вопросе об удалении не показывается. Иначе каждый заход в Видеостудию заводил «фильм» в проекте.
